# Implementation Plan: Buildings — Nutrient Farms, Booster Factories, Harvesters

**Branch**: `002-buildings` | **Date**: 2026-10-25 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-buildings/spec.md`

## Summary

Adds buildings as a second way to spend nutrients. Technically, a building is a record plus a
per-cell lookup in the existing deterministic sim; placement is one new command
(`placeBuilding`) validated by one shared function (`canPlace`) that both the command and the UI
preview use. The nutrient farm is built as a **source of supply**: it reuses the source
mechanism that food cells and the core already use, so income, flow thickness, and orphan logic
work with a single extra condition. Costs and upkeep come out of the owning piece's pool, and
the starvation rule from 001 is the only brake besides a per-type limit. The UI is a comic build
bar, a placement mode with a validity ghost, and an inked building layer. See
[research.md](research.md) for each decision and its rationale.

**Scope of this plan**: the full feature is designed (farm, booster factory, harvester, rivals),
but implementation starts with the **farm** (User Story 1). The other stories reuse the same
seams (research B9) and get their own detail when they are built.

## Technical Context

**Language/Version**: TypeScript 7.0 (strict), as in 001

**Primary Dependencies**: PixiJS 8.22, Vite 8.3, Vitest 5.0 (no new dependencies)

**Storage**: none new

**Testing**: Vitest headless for placement rules, income, upkeep, orphan behavior, destruction,
determinism and replay; manual playtest checklist for the build bar and placement feel

**Target Platform**: modern desktop browsers, as in 001

**Project Type**: single-page browser game (extends the 001 project)

**Performance Goals**: no measurable change to the sim tick (at most a handful of buildings per
mold); building layer redraws only when the set of buildings changes

**Constraints**: deterministic (no `Math.random`, no non-reproducible math in `src/sim`); the
sim stays free of DOM and Pixi imports; all numbers in `balance.ts`

**Scale/Scope**: up to 6 farms per mold in this slice; 3 building types in the full feature

**Structure Decision**: Extend the single 001 project. Sim changes stay inside `src/sim` behind the
existing public API; the only new public function is `canPlace`. The import-boundary tests from
001 keep covering the sim.

## Delivery Order (input to `/speckit-tasks`)

1. **Foundation**: types, balance table, world arrays, invariants, hash, destruction with the cell.
2. **US1 Nutrient Farm (P1)**: `canPlace` and `placeBuilding`, farm income and upkeep, source and
   orphan behavior, build bar, placement mode and ghost, farm drawing, playtest. **Built first.**
3. **US2 Booster Factory (P2)**: after 001's combat story exists.
4. **US3 Harvester (P2)**: needs food sizes from 001; can ship right after the farm.
5. **US4 Rivals build (P3)**: after 001's rival AI exists.

## Risks

| Risk | Mitigation |
|---|---|
| Farms become the dominant strategy | Fixed limit, upkeep, and a modest yield next to food drops; numbers live in `balance.ts` and are tuned with the batch sim |
| Placement UI conflicts with click-to-grow | Placement is an explicit mode; outside it, controls are unchanged |
| Building cells starving unfairly | Starvation spares building cells while other leaves exist |
| Preview and command disagree | Both call the same `canPlace` |
